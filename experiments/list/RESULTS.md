# A doubly-linked list: what it wins, what it costs, and what safe cursors cost

From `bench.txt`, generated by `./run.sh` (`-count=6 -benchtime=100ms`).
Provenance in that file's header; a QEMU guest, so **ratios are the durable
result**. Zero-cost baseline `BenchmarkNoOp` = 0.2 ns.

## 1. Removal by handle is flat; a slice is linear

Removing the middle element and splicing it back, so neither side rebuilds its
fixture inside the timed loop:

| n | list | slice | ratio |
|---|---|---|---|
| 64 | 1.6 ns | 9.6 ns | 6x |
| 1 024 | 1.6 ns | 159.9 ns | 100x |
| 16 384 | 1.6 ns | 1 829.5 ns | 1 143x |
| 262 144 | 1.6 ns | 30 353.8 ns | **18 971x** |

The list is O(1) and does not move with n. The crossover is below 64 elements,
so there is essentially no size at which the slice wins.

## 2. Pointer chasing costs 4x — and the iterator hides all of it

This is the standard objection to linked lists, and it has to be measured
against a like-for-like traversal.

| n = 262 144 | list | slice | ratio |
|---|---|---|---|
| raw loop | 193 855 ns | 50 201 ns | **list 3.9x slower** |
| through `iter.Seq` | 294 875 ns | 295 687 ns | **identical** |

Raw, the cache penalty is real and large. Through an iterator it vanishes: the
closure costs more than the cache misses do, and both structures pay it equally.

**Every container in this package is iterated through `All()`.** So the
iteration penalty a caller can actually observe is zero. A benchmark comparing a
list's `iter.Seq` against a raw slice range would have reported ~5.9x and
attributed it to pointer chasing; that comparison measures the iterator.

## 3. Validating a cursor is free; the back-pointer that enables it is not

Per-access cost of checking a cursor before dereferencing it:

| | ns |
|---|---|
| unchecked | 0.3 |
| tombstone (removed node's `prev` points at itself) | 0.4 |
| back-pointer (`node.list != l`) | 0.4 |

**Indistinguishable.** The branch inlines and predicts, so validation is free at
the call site whichever mechanism is used.

The cost is structural, and only the back-pointer pays it:

| | node, V=int | node, V=string | GC cycle, 200k retained | build 65 536 |
|---|---|---|---|---|
| 2 pointers | 24 B | 32 B | 1 414 773 ns | 1 125 084 ns |
| 3 pointers | **32 B (+33%)** | **40 B (+25%)** | **1 537 531 ns (+8.7%)** | 1 299 175 ns (+15%) |

Baseline GC cycle with nothing retained is 124 548 ns, so the retained list
dominates that measurement and the third pointer adds 8.7% to it.

## 4. The two mechanisms differ in exactly one case

| | stale cursor | cursor from another list |
|---|---|---|
| tombstone | caught | **undetected** |
| back-pointer | caught | caught |

The tombstone catches staleness for nothing — no extra field, same free check.
**The back-pointer's entire purchase is the foreign-cursor case**, and its price
is +25-33% per node and +8.7% per GC cycle.

## Conclusions

Durable:

1. Removal by handle is O(1) and beats a slice at every size measured, by four
   orders of magnitude at the top end.
2. Pointer chasing costs ~4x on a raw traversal and **nothing** through an
   `iter.Seq`, because the closure dominates. Comparing a list's iterator
   against a raw slice range measures the iterator, not the list.
3. Cursor validation is free at the call site regardless of mechanism.
4. A tombstone catches stale cursors at zero structural cost. A back-pointer
   additionally catches foreign cursors, for +25-33% memory and +8.7% GC.

Perishable: every absolute number above.
