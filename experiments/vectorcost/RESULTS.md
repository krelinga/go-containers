# What a container wrapper costs a slice

From `bench.txt`, generated by `./run.sh` (`-count=10 -benchtime=200ms`).
Provenance in that file's header; a QEMU guest, so **ratios are the durable
result**. Zero-cost baseline `BenchmarkNoOp` = 0.23 ns. Sums are over 1024
elements; per-element figures are derived.

## 1. A single element read is free

| | |
|---|---|
| `s[i]` | 0.374 ns |
| `v.At(i)` | 0.347 ns |

Indistinguishable — the forwarding method inlines away, exactly as `dispatch`
and `hashdict` found for map operations.

## 2. An indexed loop costs 24%, because the bounds check survives

| sum of 1024 elements | | per element |
|---|---|---|
| `for _, x := range s` | 200.9 ns | 0.196 ns |
| `for i := 0; i < len(s); i++ { s[i] }` | 196.7 ns | 0.192 ns |
| `for i := 0; i < v.Len(); i++ { v.At(i) }` | **244.8 ns** | **0.239 ns** |

The compiler says why. Asked directly with
`-gcflags='-d=ssa/check_bce/debug=1'`, the indexed slice loop reports nothing —
its bounds check was eliminated — while the check inside the accessor survives:

```
./shapes.go:22:50: Found IsInBounds     // func (v *Vector[T]) At(i int) T { return v.es[i] }
./shapes.go:23:43: Found IsInBounds     // func (v *Vector[T]) Set(i int, e T)
```

`i < len(s)` proves the index safe; `i < v.Len()` indexing into `v.es` does not,
because nothing ties `v.Len()` to `len(v.es)` at the point of use. **This is the
one cost a sequence wrapper has that a map wrapper does not** — a map has no
bounds check to lose.

Note it appears only in a loop. A single `At` is free (section 1); what is lost
is the *elimination* across repeated indexing.

## 3. The iterator costs 5.9x, and the wrapper adds 3% of that

| sum of 1024 elements | | per element | vs raw range |
|---|---|---|---|
| `for _, x := range s` | 200.9 ns | 0.196 ns | — |
| `for x := range slices.Values(s)` | 1.156 µs | 1.13 ns | **5.8x** |
| `for x := range v.All()` | 1.194 µs | 1.17 ns | 5.9x |
| `for _, x := range v.AllIndexed()` | 1.203 µs | 1.17 ns | 6.0x |

This is the number that matters most, and it is **not** a cost of the container.
`slices.Values(s)` — pure stdlib, no wrapper — already costs 5.8x. `Vector.All`
adds **3.3%** on top of that.

The 6x matches what `linkedlist` measured for iterator abstraction generally. The
library committed to `iter.Seq` as its interchange in ADR `0006` and `0008`;
against a slice that commitment is expensive in proportion, because raw slice
iteration is so cheap. **A Vector inherits that cost rather than introducing it.**

## 4. The variadic signature costs more than the container does

| append one element, presized | | overhead |
|---|---|---|
| `s = append(s, 1)` | 0.5715 ns | — |
| `v.AppendOne(1)` — non-variadic | 0.6570 ns | **+15%** |
| `v.Append(1)` — variadic `...T` | 0.9279 ns | **+62%** |

The container costs 15%. The `...T` signature costs another 41 points on top.

ADR `0002` made mutators variadic, and for a set that is invisible: `Add` is a
map insert at ~5 ns, so 0.27 ns of variadic overhead is noise. Append is 0.57 ns,
so the same absolute overhead is half the operation again. **The same convention
lands very differently on a sequence.**

## 5. What the wrapper buys

```
slice: two appends off one header -> x[1]=2 y[1]=2  aliased=true
slice: callee appended, caller sees Len=0  (the append is lost)
vector: callee appended, caller sees Len=2
vector: after 8 reallocating appends, an aliasing holder sees Len=8
```

Three distinct hazards, all from the same cause — a slice header is a *value*, so
every holder has their own copy of the length and the backing pointer:

- **Appends off a shared header alias.** With spare capacity, two appends write
  the same backing cell and the first result is silently overwritten.
- **A callee's append is invisible** unless it returns the slice and the caller
  reassigns. Nothing at the call site says so.
- **Reallocation splits holders.** Before a grow they share; after, they do not.

A `Vector` owning its slice behind a pointer removes all three: every holder
reaches the same header, so an append is seen by all of them and a reallocation
changes nothing observable.

## Conclusions

Durable:

1. A single element read through the wrapper is free; the forwarding inlines.
2. An indexed loop through the wrapper costs ~24%, because bounds-check
   elimination does not survive `v.Len()`/`v.At(i)`. Confirmed against the
   compiler's own BCE report. This is the one overhead a sequence wrapper carries
   that a map wrapper does not.
3. Iterating through `iter.Seq` costs ~6x raw ranging, and that is the stdlib's
   price, not the container's — `slices.Values` pays 5.8x of it. A container's
   `All` adds ~3%.
4. Variadic mutators cost ~40% of an append. Cheap for a map-backed container
   where the operation is ~5 ns; expensive for a sequence where it is ~0.6 ns.
5. Reallocation is observable through a slice header in three distinct ways —
   aliased appends, lost appends, and holders splitting at a grow. Owning the
   slice behind a pointer removes all three.

Perishable: every absolute number above.
