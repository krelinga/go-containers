# What it costs to make a container a reference type

From `bench.txt`, generated by `./run.sh` (`-count=20 -benchtime=300ms`).
Provenance in that file's header; a QEMU guest, so **ratios are the durable
result**. Zero-cost baseline `BenchmarkNoOp` = 0.27 ns.

Widths: `*PtrSet` 8 B, `RefSet` 8 B, `NilSafeSet` 8 B, interface 16 B.

**Compare only within a benchmark group.** The same operation measured in two
different groups differed by ~6% here (312.2 ns against 331.6 ns for the same
`AllInner`), which is measurement context rather than an effect. Every table
below is one group.

## 1. A reference struct costs nothing over today's pointer

| | `Has` | `Len` | `Add` | `All` (64 elems) | construct |
|---|---|---|---|---|---|
| `*PtrSet` — ADR 0002's shape | 2.933 ns | 0.366 ns | 73.6 ns | 360.0 ns | 26.4 ns |
| `RefSet` — struct wrapping a pointer | **2.993 ns** | **0.374 ns** | **72.7 ns** | **325.9 ns** | **26.2 ns** |

Indistinguishable everywhere, and zero allocations on every read for both.

The extra hop is not extra. Today a method reads `s.m` having already
dereferenced `s`, which is a pointer; a reference struct reads `s.st.m`, where
`s` is a one-word value already in a register. Both are a single load. Reference
semantics is free at the representation level — **what it costs is paid in
rules, not cycles.**

## 2. The nil check costs ~10% on a point read and nothing on iteration

Reproducing builtin-map semantics — a zero container reads clean and panics on
write — needs a nil check in every read method, which is what ADR 0002 bans.

| | `Has` | `Len` | `All` |
|---|---|---|---|
| `RefSet` (no check) | 2.993 ns | 0.374 ns | 325.9 ns |
| `NilSafeSet` (checked) | **3.247 ns (+8.5%)** | 0.405 ns | 312.2 ns |

A predictable branch on a hot path: about a quarter of a nanosecond, against a
map lookup of three. On iteration it does not register, because the check runs
once per `All` rather than once per element.

Iterating a zero container costs **0.88 ns and no allocations** — it yields
nothing, exactly as ranging a nil map does.

## 3. Where the nil check goes in `All` decides whether it allocates

| `All` over 64 elements | | allocs |
|---|---|---|
| check **before** the closure, early-returning an empty one | 360.4 ns | **2, 40 B** |
| check **inside** the closure | **331.6 ns** | **0** |

Two return statements yielding two different closures is enough to put the
closure on the heap. One closure and one return keeps it on the stack.

This inverts ADR `0002`'s eager-dereference rule, which exists so a nil
container panics at the call rather than at iteration. Under builtin-map
semantics a read has nothing to panic about — ranging a nil map yields nothing —
so the rule has no work to do on reads. **It still applies to writes**, which
must panic, and to any method that must fail loudly.

## 4. The interface form costs 25% on reads and allocates on every `All`

| | `Has` | `Len` | `All` | `All` allocs |
|---|---|---|---|---|
| `RefSet` | 2.993 ns | 0.374 ns | 325.9 ns | 0 |
| sealed interface | **3.672 ns (+23%)** | **1.025 ns (+174%)** | **396.7 ns (+22%)** | **3, 64 B** |

Two separate costs.

**Dispatch, and the inlining it prevents.** `dispatch` measured interface
dispatch at ~0.7 ns; the same figure here, but as a *share* it is large because
container operations are cheap. `Len` is the extreme: a length read is 0.37 ns
direct and 1.03 ns through an interface, because there is nothing else in it.

**Returning a closure through a dynamic call allocates.** `All` returns an
`iter.Seq`, and through an interface the closure cannot be stack-allocated at the
range site: three allocations, 64 bytes, **on every call**. Direct calls on any
struct form are zero.

That second cost is the one to weigh. It applies to iteration, which is the
operation a container exists for, and it does not amortise the way a
construction-time allocation does.

### This already applies to ADR 0013's views

Views became sealed interfaces in ADR `0013`, so the same cost is live in the
shipped library. Measured against `containers` at HEAD:

```
All  direct on the container = 0 allocs   via the view interface = 3 allocs
Get  direct on the container = 0 allocs   via the view interface = 0 allocs
```

`experiments/viewiface` measured `Get` through an interface and never `All`, so
ADR `0013`'s "one allocation per view, at construction, amortised over every
use" is true of point reads and **not** of iteration. Iterating a view allocates
three times per call, every call. Whether that changes anything is a question for
`0013`, not this experiment; it is recorded here because it is evidence about the
representation either way.

## 5. Only a struct can reproduce builtin-map semantics

| | `x == nil` compiles | `Len` when zero | read when zero | range when zero | write when zero |
|---|---|---|---|---|---|
| builtin `map` | ✓ | 0 | zero value | 0 iterations | **panics** |
| `RefSet` (no check) | ✗ | panics | panics | panics | panics |
| `NilSafeSet` (checked) | ✗ | **0** | **zero value** | **0 iterations** | **panics** |
| sealed interface | **✓** | **panics** | **panics** | panics | panics |

The trade is exact and inescapable: **a struct can match the semantics but not
the syntax; an interface can match the syntax but not the semantics.** A nil
interface has no dynamic type, so every method call panics — there is no way to
make a read on it succeed.

Only `map` itself gets both, which is why `Map[K, V]` can be a defined `map[K]V`
and nothing else can follow it there.

Two representations that would have squared the circle do not exist:

```
type SortedSet[T any] *state[T]   // invalid receiver type (pointer or interface type)
type SortedSet[T any] []T         // nil-comparable, but Add must replace the header,
                                  // which needs a pointer receiver -- so not a reference
```

## 6. Reference semantics fixes the copy that started this repository

```
value copy:     original Len=1, copy Len=2  -> diverged
reference copy: original Len=2, copy Len=2  -> shared
```

A slice header must be replaced when it grows, so a container that holds one
inline diverges when copied. That is the aliasing surprise this library was begun
over, and it is why `noCopy` exists. Holding the state behind a pointer makes a
copy *be* the same container, like a map — the surprise stops existing rather
than being caught.

## 7. The interface form removes ADR 0002's set-algebra ceiling

ADR `0002` recorded that `Union`, `Intersect` and `Difference` cannot go on a
contract, because Go has no covariant returns. Verified, under today's shape:

```
*PtrSet[int] does not implement SetAlgebra[int] (wrong type for method Union)
        have Union(*PtrSet[int]) *PtrSet[int]
        want Union(SetAlgebra[int]) SetAlgebra[int]
```

If the container **is** the interface, the two types are the same and it
compiles — `Union(IfaceSet[T]) IfaceSet[T]` satisfies itself. A ceiling standing
since `0002` disappears.

It is the only thing the interface form wins that the struct form does not, and
it is worth naming plainly against the 25% and the per-`All` allocations.

## Conclusions

Durable:

1. A reference struct is indistinguishable from today's pointer-to-noncopyable
   on every operation measured, including allocations. The indirection is not an
   extra hop.
2. A nil check on reads costs ~8.5% of a point read and nothing measurable on
   iteration. Builtin-map semantics is affordable.
3. The check must sit **inside** the returned closure in `All`. Placing it before
   gives two closures, two return paths, and two heap allocations per call.
4. An interface container costs ~23% on point reads, more on the cheapest ones,
   and **3 allocations per `All` call** because a closure returned through a
   dynamic call cannot be stack-allocated. Neither is amortisable.
5. A struct can reproduce builtin-map nil semantics but cannot be compared to
   nil; an interface can be compared to nil but panics on every read when nil.
   Only a defined map type gets both.
6. Reference semantics dissolves the copy-divergence hazard rather than catching
   it, which is what `noCopy` and copylocks exist for today.
7. Set algebra type-checks on a container interface, and only there.

Perishable: every absolute number above.
